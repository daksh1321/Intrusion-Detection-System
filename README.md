# Intrusion Detection System (IDS) using CNN-LSTM

An academic Intrusion Detection System project built with Python and deep learning. It uses the CIC-IDS2017 network-flow dataset to classify traffic into **BENIGN** and multiple attack categories.

## Project status

- Dataset preprocessing scripts are included.
- A baseline SGD classifier and an autoencoder anomaly detector are included.
- A CNN-LSTM multiclass classifier is included.
- A memory-efficient test script evaluates the trained CNN-LSTM on the prepared test set.
- The reported test run evaluated **531,518 sequences** and obtained **99.45% accuracy**, **99.40% weighted F1**, and **63.71% macro F1**. Results are specific to the current split and sequence construction; they should not be interpreted as guaranteed performance on unseen real-world traffic.
- Rare classes such as Heartbleed, Infiltration, and Web Attack - Sql Injection have very few test examples, so their class-specific scores are not reliable.

## Dataset

This project uses **CIC-IDS2017** from the Canadian Institute for Cybersecurity.

Official dataset page: <https://www.unb.ca/cic/datasets/ids-2017.html>

Download the CIC-IDS2017 CSV flow files and place them in:

```text
data/raw/CIC-IDS2017/
```

The scripts expect these eight CSV files:

```text
Monday-WorkingHours.pcap_ISCX.csv
Tuesday-WorkingHours.pcap_ISCX.csv
Wednesday-workingHours.pcap_ISCX.csv
Thursday-WorkingHours-Morning-WebAttacks.pcap_ISCX.csv
Thursday-WorkingHours-Afternoon-Infilteration.pcap_ISCX.csv
Friday-WorkingHours-Morning.pcap_ISCX.csv
Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv
Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv
```

Dataset files are not stored in this Git repository because they are large. Processed datasets, trained models, and NumPy arrays are also excluded by `.gitignore` and must be generated locally.

## Requirements

- Python 3.11 recommended
- Windows, Linux, or macOS; commands below use Windows PowerShell
- Sufficient disk space and RAM for CIC-IDS2017 processing and training
- CPU execution is supported. Native Windows TensorFlow may not use NVIDIA CUDA GPUs with TensorFlow 2.11 or later.

Install dependencies:

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Setup and run

Run commands from the repository root.

### 1. Check the dataset files

```powershell
python src/01_check_files.py
python src/02_inspect_files.py
```

### 2. Prepare the dataset

Run the available preprocessing scripts in order, checking each script's output before continuing:

```powershell
python src/03_combine_files.py
python src/05_label_distribution.py
python src/06_preprocess.py
python src/07_verify_preprocessed.py
python src/08_train_test_split.py
python src/09_verify_split.py
python src/10_inspect_features.py
python src/11_prepare_features.py
python src/12_final_preparation.py
```

The preprocessing scripts may create large files under `data/processed/`. Keep these local rather than committing them to Git.

### 3. Train a model

For the primary CNN-LSTM model:

```powershell
python src/17_train_cnn_lstm.py
```

The training script expects the processed arrays and label mapping generated by the preparation pipeline.

### 4. Evaluate the trained CNN-LSTM

After training, run:

```powershell
python src/20_test_cnn_lstm.py
```

This script expects these generated files under `data/processed/`:

```text
IDS_CNN_LSTM.keras
X_test_scaled.npy
y_test.npy
label_mapping.json
```

It evaluates sequences of 10 flows in batches to reduce memory use, and saves the test metrics and confusion matrix under `data/processed/`.

- Web Attack - Sql Injection
- Web Attack - XSS

## Important notes

1. **Run scripts from the repository root** so the expected relative paths resolve correctly.
2. The scripts are numbered to indicate the general workflow, but `04_verify_combined.py` is not currently present in the repository listing. Follow the scripts that are actually available in `src/`.
3. The CNN-LSTM expects sequences with shape `(10, 70)`, not one isolated flow. Predictions are made for the final flow in each sequence.
4. A high overall accuracy can hide poor performance on rare classes. Review per-class precision, recall, F1, and the confusion matrix.
5. The current evaluation uses the project's existing train/test split and sequence construction. A time-based or capture-based holdout would provide a stronger test of generalization to new traffic.
